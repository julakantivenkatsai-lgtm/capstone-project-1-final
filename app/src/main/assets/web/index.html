Isolation Forest Anomaly Detection

Unsupervised anomaly score calculation using recursive binary space partitioning.

Core Engineering Principle: An Anomaly ≠ A Machine Failure.
An anomaly score indicates that the machine's telemetry (e.g. unusual combination of torque and rpm or thermal differential) sits in a low-density region of the operating phase space. An anomalous machine might be undergoing an unexpected load cycle without suffering immediate failure.

Anomaly Score Distribution

Threshold ≥ 0.58 flags anomalous operational states. Score formula: s(x, n) = 2^(-E(h(x)) / c(n)).

Academic Methodology, Architecture & Limitations

Computer Science and Engineering (CSE) Final-Year Project Specifications.

1. System Architecture & Objectives

MaintIQ (Machine Health Intelligence) addresses the challenge of unplanned industrial equipment downtime by synergizing supervised machine learning classifiers (Logistic Regression, Random Forest, and Gradient Boosted Decision Trees / XGBoost) with unsupervised anomaly detection (Isolation Forest). The platform operates client-side with zero external API dependencies, ensuring industrial telemetry privacy and offline operational capability.

2. Dataset Disclosure & Preprocessing Rigor

The experimental evaluation employs the UCI AI4I 2020 Predictive Maintenance Dataset (Matan et al.), comprising 10,000 synthetic instances reflecting real milling tool physics.

  • Synthetic Data Disclosure: The dataset is synthetic and does not represent verified physical real-world industrial testing. It provides a standardized academic testbed for imbalanced classification.
  • Data Leakage Prevention: The failure mode indicator columns (TWF, HDF, PWF, OSF, RNF) as well as identifier columns (UDI, Product ID) are rigorously isolated and excluded from training feature vectors.
  • Stratified Train/Val/Test Split: The dataset is partitioned into 70% Training, 15% Validation, and 15% Test splits, preserving the ~3.4% failure class balance across all splits. Preprocessing scalers (Z-score parameters) are fitted strictly on the training partition.
  • Validation Threshold Tuning: In severely imbalanced classification, default 0.5 probability thresholds skew towards the majority class. The decision threshold τ is optimized on the validation partition to maximize F1-score, and reserved for final unbiased evaluation on the test partition.

3. Project Boundaries & Mandatory Limitations

No Remaining Useful Life (RUL):
MaintIQ focuses strictly on instantaneous binary failure classification and anomaly scoring. It does not predict Remaining Useful Life (RUL) run-to-failure degradation curves.
No Industrial Safety Certification:
This software is an academic engineering prototype. It is not certified for mission-critical industrial safety decisions or automated emergency shutdowns.
Anomaly ≠ Machine Failure:
An anomaly indicates unusual operating regimes (outliers in the multivariate feature space), but machines may operate safely in anomalous regimes without failure.
Feature Importance ≠ Causation:
Permutation feature importance quantifies model sensitivity to individual inputs. It does not prove physical mechanical causality and is not Shapley (SHAP) values.
